# REV Journal 1 - 04/06/2026

Welcome back! New project time, this time a delay module :)

I've already done a tiny bit of research, and I've opted to go for a digital circuit this time, as if I were using a BBD (bucket-brigade device) I wouldn't really be able to simulate it and I don't trust my analogue skills enough to make the changes I'd need to make the circuit my own. 

For the digital chip, I've decided to go with the rp2040. The main reason is just because I'm exceedingly familiar with it, I've made several projects utilising it successfully already, and it also has really good documentation and support (being the main chip in the RP Pico). Its ADC should be adequate, as it has a sampling rate of 500kHz, well above the 44.1kHz requirement I'd want. For output, I could either use a DAC, or try and finagle something with pwm. The PWM approach is quite apealling, as it reduces cost, complexity, and latency, but it might result in a bit of audio quality decrease.

The main problem with PWM is you get a lot of the carrier signal in the output. If your pwm is running at ~10khz, there will be buzzing at 10kHz. A couple options for this are to chuck the pwm frequency outside of audible range, ~100kHz would probably be fine. Given the rp2040 can run at a clock speed of up to 133MHz (nvm its 200MHz actually lol), it should probably be fine to take this approach. The only downside is that this does take processing time, which I'd really like to dedicate to the actual audio processing. Overall though I think I will go with pwm audio.

### Audio output

I'm pretty much just stealing the circuit from the hardware guide: 
A seperate ldo for audio, and then buffering and filtering. Instead of the suggested logic buffer, I'm using a logic inverter, as theres no buffers in the basic parts list and inverters do pretty much the same thing ;)

![Output section](https://cdn.hackclub.com/019e91b9-f14b-77aa-b9fb-ed89094fa108/paste-1780561339594.png)

### Audio input

The audio input is pretty basic, first just make sure its centered around ground, then divide it down to ~2.8V p2p assuming that the input is from -5 to 5v. I went for 2.8V just in case the input goes a bit high, so that the input doesn't get fried lol.
Finally, I bias it to ~1/2 of 3.3V so that the full range of the wave can be captured by the adc, buffer it, and send it off to the mcu.

![Audio input section](https://cdn.hackclub.com/019e91c5-f6a7-7af4-a8db-2959d3618cb7/paste-1780562127392.png)
